Core Chapter: Solución de Automatización y Mejora Operativa (TO-BE)

6.1 Descripción del Proceso TO-BE

El proceso de atención, verificación y despacho de asistencias de Soluciones W pasa de ser un embudo manual telefónico/chat no estructurado a un ecosistema de autoservicio omnicanal 24/7 en tiempo real. El usuario interactúa a través de WhatsApp oficial con mensajes interactivos nativos de Meta (listas y menús) gestionados por Vocero CRM, el cual orquesta la verificación criptográfica del afiliado y el despacho instantáneo de asistencias mediante la API REST de Soluciones W, manteniendo un escalado asistido a humanos (human-in-the-loop) únicamente para excepciones. ──────

6.4 Descripción Funcional de la Solución

• Interacción Estructurada sin Errores de Tipeo: Sustitución de texto abierto por listas interactivas nativas de Meta (type:"interactive"), eliminando respuestas ambiguas. • Integración Desacoplada: Vocero CRM consulta los microservicios de Soluciones W vía REST sin exponer la base de datosinterna. • Sesiones Efímeras (Ventana 24h): Reinicio automático del flujo ante inactividad > 24h para garantizar contexto fresco.• Resolución del AS-IS: Elimina los cuellos de botella de digitación manual, tiempos de espera de hasta 20 minutos y pérdidade trazabilidad de radicados. ──────

6.5 Roles de Usuario e Interacciones

• Afiliado (Externo): Solicita asistencias en 3 clics y recibe radicado con ETA de despacho. • Prospecto (Externo): Consulta catálogo de planes y accede a pasarela de pagos. • Asesor de Operaciones (Interno): Visualiza en el Inbox de Vocero CRM todas las conversaciones; interviene solo cuando elsistema escala el caso (handoff). • Coordinador de Despacho (Interno): Monitorea en el panel de Soluciones W las solicitudes creadas bajo el canal whatsapp.──────

6.6 Lógica de Automatización y Reglas de Negocio

Regla de Cédula: Longitud de 6 a 11 dígitos numéricos. • status === "active" → Habilita menú de despacho y Magic Link. • status === "past_due" → Bloquea despacho y entrega canal de cartera. • not_found → Ofrece catálogo de afiliación.

Regla de Handoff: Cualquier solicitud explícita de agente o selección de opt_hablar_asesor silencia al bot en base dedatos (handoff_at = NOW()) y asigna el chat a la cola humana.

Regla de Saludo / Timeout: Saludo con historial vacío o último mensaje > 24h → Despliega menú interactivo raíz. ──────

6.7 KPIs Operativos Post-Implementación

• Tiempo Medio de Radicación (TMR): De 12–18 minutos a < 45 segundos (-95%). • Disponibilidad Operativa: De horario de oficina (8h/día) a 24/7/365 (100% uptime). • Tasa de Desvío a Autoservicio: 82% de las consultas resueltas sin intervención humana. • Precisión de Datos (Error Rate): De 15% de errores de digitación de cédula/servicio a 0% (validación estructurada por API).──────

Arquitectura Técnica y Diseño del Ecosistema

7.1 Enfoque Arquitectónico

• Arquitectura Cloud Nativa (IaaS / Dockerizada): Alojada en una máquina virtual de Oracle Cloud Infrastructure (ARM64 Ampere - 4 OCPUs, 24 GB RAM) en Ashburn. • Justificación: Alta eficiencia de costos, baja latencia internacional, aislamiento en microservicios mediante redes internas de Docker y escalabilidad horizontal. ──────

7.2 Sistemas, Herramientas y Plataformas

• Meta WhatsApp Cloud API (v21+): Gateway oficial de mensajería empresarial para mensajería interactiva. • Vocero CRM (Next.js 15 Standalone + Node.js 22 + PostgreSQL 16): Orquestador de webhook, persistencia de chats, SSE entiempo real y panel de asesor humano. • Soluciones W Core (Next.js 16 + React 19 + API Routes): Fuente única de verdad para lógica de afiliados, convenios y contratos. • Traefik Reverse Proxy + Cloudflare DNS: Enrutamiento perimetral, balanceo de carga y terminación SSL/TLS automática (Let'sEncrypt). ──────

7.3 Integración con Sistemas Existentes

• Tipo: RESTful APIs sobre HTTPS + Webhooks Asíncronos. • Endpoints Consumidos por Vocero CRM: • POST https://w-soluciones.jhojan.cloud/api/auth/login (Autenticación y consulta de afiliación). • POST https://w-soluciones.jhojan.cloud/api/assistances/request (Radicación de emergencias). • Seguridad de Enlace: Tokens JWT generados con clave simétrica para autenticación sin credenciales estáticas (Magic Links).──────

7.4 Flujos de Datos y Automatización

Ingreso: Webhook de Meta valida el HMAC SHA-256 del payload entrante.

Transformación: Vocero CRM extrae el ID de la opción seleccionada (list_reply.id / button_reply.id).

Consumo & Radicación: Vocero invoca Soluciones W con docNumber y serviceId.

Respuesta: Soluciones W persiste el evento en su almacén de datos, genera radicado (#AUX-XXXX) y Vocero lo entrega alusuario en menos de 2 segundos. ──────

MVP Funcional

8.1 Alcance del MVP Funcional

El MVP implementado es una solución de producción 100% operativa que cubre de punta a punta el flujo TO-BE:

Menú interactivo raíz de 4 opciones.

Consulta de cédula y retorno de estado de afiliación.

Lista interactiva de servicios de urgencia (Ambulancia, Médico, Hogar, Mascotas).

Generación de radicado con código #AUX-XXXX y Magic Link para acceso al portal web.

Handoff humano en tiempo real hacia el panel web de Vocero CRM. ──────

8.2 Código Fuente y Artefactos Desarrollados

• Vocero CRM (/opt/vocero-crm): • src/server/inbox/webhook.ts: Soporte para payloads de tipo interactive. • src/server/inbox/ingest.ts: Normalizador de respuestas de listas y botones interactivos. • src/server/inbox/send.ts: Motor de envío sendInteractiveList(...) para Meta Graph API. • src/server/integrations/soluciones-w.ts: Cliente HTTP para consumir los endpoints de Soluciones W. • src/server/ai/pipeline.ts: Lógica del flujo TO-BE, validación de cédulas, radicados y reinicio 24h. • Soluciones W (Projects/soluciones-w/frontend): • src/app/api/auth/login/route.ts: Endpoint de validación y emisión de JWT. • src/app/api/assistances/request/route.ts: Endpoint de radicación con generación de #AUX-XXXX.

8.4 Documentación Técnica de Reproducción y Despliegue

Prerrequisitos

• Node.js v22+ y pnpm v9+. • Docker & Docker Compose. • Acceso a Meta Cloud API (WABA ID y Phone Number ID).

Pasos de Despliegue y Ejecución

# 1. Clonar y levantar Soluciones W
cd Projects/soluciones-w/frontend
pnpm install
pnpm run build
pnpm run start # Puerto 3000 / 3001

# 2. Desplegar Vocero CRM en Docker
cd /opt/vocero-crm
sudo docker compose build app
sudo docker compose up -d app

# 3. Comprobación de Healthcheck
curl -i https://crm.jhojan.cloud/api/health
# Respuesta esperada: {"ok":true,"version":"1.4.0","commit":"b3469f9","commitVerified":true}

# 4. Prueba del Endpoint de Integración
curl -s -X POST https://w-soluciones.jhojan.cloud/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"docNumber":"1018492031"}'
